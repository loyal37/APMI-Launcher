# APMI Launcher current state

Snapshot updated on 2026-11-26. Times below use Asia/Shanghai.

## Source and local build

- Launcher 0.2.0 adds MCP support. The Windows x64 release uses a clean self-contained build. The local working DLL at `dist/APMI/d3d11.dll` reports version 1.3.3.0.
- The Settings switch `MCP Capture` persists `EnableMcp` and controls probe injection on the next launch. The default is false. The user's current local settings have it enabled, saved through the UI for real-game verification.
- The bundled MCP server exposes 34 `apmi_*` tools, using probe 0.1.18-apmi.1 and Python capture backend 0.1.27. The probe is `dist/mcp/dist/apmi_probe.dll`. Client configuration is generated at `dist/mcp-config.json`. Python 3.12 runs the server over stdio. Shared reload/mod-switch, OBJ/raw mesh export, recording/replay and texture fingerprint tools are included. Slot-cache work is deferred by the user's request.
- The active `dist/APMI` runtime has APMI Core 0.2.2 DEV from `F:\APMI Package` with XXMI 1.3.3. The exporter uses LoyalTools' EFMI merged-template entry points, draw command lists and resource naming. The final installation backup is in the APMI Package workspace at `build/deployment-20261126-135413-be1e47/`.
- On 2026-11-26, the user requested the Launcher v0.2.0 release and a separate APMI Package source submission. APMI Package `main` contains source commit `68786e6` with Core 0.2.2.
- The v0.1.1 Windows x64 package uses a small launcher EXE with separate application and .NET runtime DLLs. A fresh copy starts with empty game, official launcher and package paths. The local release archive is `build/releases/v0.1.1/APMI-Launcher-v0.1.1-win-x64.zip`. [README](../README.md)
- Local evidence paths under `build/` and `dist/` refer to this workspace. Build requirements and the worker flow are in [Architecture](ARCHITECTURE.md).
